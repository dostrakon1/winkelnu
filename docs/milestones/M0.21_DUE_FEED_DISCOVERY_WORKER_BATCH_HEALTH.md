# M0.21 — Due Feed Discovery, Worker Batch Execution & Operational Health

Status: repository-side implemented; CI verification pending.

## Delivered
- due-feed discovery port;
- Supabase due-feed discovery implementation;
- bounded batch worker (default 10, hard cap 50);
- per-feed execution through the existing M0.20 exclusive lease;
- independent batch result accounting;
- health classification: healthy, delayed, failing, attention_required;
- tests for success/failure batches, lease races, batch cap and health states;
- architecture documentation.

## Safety properties
Discovery never grants execution authority. Every source must still acquire its atomic lease. A failure in one source is recorded and scheduled independently and does not abort unrelated feeds. Storefront reads are not coupled to worker health.

## External gates
- live Supabase migration 0006 not yet applied;
- no production scheduler trigger configured;
- Daisycon account/program/feed credentials remain external;
- bol.com and other provider adapters remain future integrations.
