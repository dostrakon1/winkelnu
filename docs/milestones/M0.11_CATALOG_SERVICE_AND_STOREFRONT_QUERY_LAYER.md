# M0.11 — Catalog Service & Storefront Query Layer

Status: Completed repository-side
Date: 2026-09-03

## Goal

Prevent Next.js storefront routes from depending directly on persistence repositories, Supabase, feed adapters or synthetic catalog implementation details.

## Implemented

- Added `CatalogService` as the storefront-facing application query layer.
- Added product listing query with best-offer resolution.
- Added product-detail query with merchant resolution.
- Added category query.
- Offer ranking uses total purchase amount: product price plus known shipping cost.
- Added a storefront composition root that chooses the configured persistence implementation.
- Memory mode bootstraps deterministic synthetic catalog data for development.
- Supabase mode uses the same service API without changing storefront routes.
- Homepage no longer imports synthetic catalog infrastructure directly.
- Product detail route no longer imports synthetic catalog infrastructure directly.
- Removed technical synthetic/import diagnostics from the public homepage.
- Added automated tests for offer ranking, listing selection and missing products.

## Architecture after M0.11

```text
Next.js route
  ↓
CatalogService
  ↓
CatalogReadRepository port
  ↓
InMemoryCatalogRepository | SupabaseCatalogRepository
```

Feed ingestion remains a separate write path:

```text
FeedAdapter → importFeed use case → CatalogWriteRepository
```

The storefront therefore does not depend on feed implementation details.

## Ranking rule

For the current baseline, offers are ranked by known landed purchase amount:

`offer price + shipping cost`

This is intentionally better than ranking only by headline product price. Future ranking may also account for delivery estimate, merchant quality, sponsorship rules and user-selected preferences, but those must be explicit and auditable.

## Acceptance criteria

- [x] Storefront routes do not call repositories directly.
- [x] Storefront routes do not import synthetic feed/catalog helpers directly.
- [x] Storefront query behavior is persistence-independent.
- [x] Merchant identity is resolved at application-service level.
- [x] Offers are deterministically ranked.
- [x] Product listing exposes best offer and offer count.
- [x] Product detail exposes ranked offers.
- [x] Core service behavior has automated tests.
