# M0.12 — Category & Discovery Query Architecture

Status: Completed (repository-side)
Date: 2026-09-03

## Goal

Introduce durable, SEO-safe category discovery above the catalog service without coupling Next.js pages to persistence details.

## Implemented

- `CatalogService.getCategory(slug)` for stable category resolution.
- `CatalogService.getCategoryDiscovery(...)` with bounded pagination.
- Look-ahead pagination (`pageSize + 1`) to determine whether a next page exists without requiring a separate count query.
- Discovery ranking that prefers products with active offers and orders visible results by known total purchase price including shipping.
- Public route `/categorie/[slug]`.
- First category page indexable with stable canonical URL.
- Paginated category pages use their own canonical URL but are `noindex,follow` to avoid uncontrolled pagination indexation.
- Invalid/empty deep pages return 404 instead of creating thin crawlable pages.
- Accessible previous/next navigation with `rel=prev` / `rel=next`.
- Homepage category discovery links.
- Sitemap now includes durable category and product URLs, but not paginated discovery URLs.
- Automated service tests for category resolution and pagination behavior.

## SEO rules

1. `/categorie/<slug>` is the durable indexable category entity.
2. Pagination is a navigation mechanism, not a separate SEO landing-page strategy.
3. Query/filter combinations are not automatically indexable.
4. Empty deep pagination pages return 404.
5. Product and category URLs are the only catalog discovery URLs added to the sitemap in this milestone.

## Ranking rule

The current deterministic discovery ordering is intentionally simple:

1. products with an active offer before products without one;
2. lower known total purchase price first, including known shipping cost;
3. title fallback where no active offer exists.

This is not yet a commercial ranking algorithm. Sponsored placements, popularity, quality, relevance and personalization require explicit future policy and transparency rules before introduction.

## Acceptance criteria

- [x] Category pages use `CatalogService`, not repositories directly.
- [x] Category slugs resolve through the catalog layer.
- [x] Pagination is bounded and deterministic.
- [x] First pages are canonical/indexable.
- [x] Deeper pagination does not create uncontrolled indexable pages.
- [x] Empty deep pages do not remain crawlable thin pages.
- [x] Sitemap includes durable categories/products only.
- [x] Category discovery behavior is covered by automated tests.
