# M0.46 — Operator Recovery Hardening & Safe Error Boundary

Status: repository-side implemented; exact HEAD CI verification pending.

## Goal
Close the remaining recovery hardening gaps from M0.37 without expanding the operator mutation surface.

## Implemented
- authorization before any idempotency request claim;
- repeated authorization in the audited action service remains as defense in depth;
- denied read-only actions leave the idempotency ledger untouched;
- operator-facing recovery failures are sanitized and never echo raw internal errors;
- automated test proves raw Supabase/RPC details are not returned by the safe error boundary;
- explicit 90-day minimum retention policy for `operator_action_requests`;
- no automatic cleanup/delete capability added;
- database contract verification now requires the retention policy metadata.

## Safety boundary
M0.46 adds no new feed mutation, recovery RPC or browser-visible diagnostic payload. Existing trusted server-side audit/idempotency evidence remains available for operations.
