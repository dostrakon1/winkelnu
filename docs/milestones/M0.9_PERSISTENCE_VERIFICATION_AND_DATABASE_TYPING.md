# M0.9 — Persistence Verification & Database Typing

Status: Repository implementation complete; live Supabase verification pending external project activation.
Date: 2026-09-03

## Objective

Make persistence assumptions testable before any real affiliate catalog depends on Supabase.

## Implemented

- Fixed M0.8 TypeScript nullability/narrowing errors discovered by GitHub Actions.
- Added migration contract verification through `npm run check:db-contract`.
- Added the database-contract check to GitHub Actions.
- Added a read-only live Supabase smoke test through `npm run verify:supabase`.
- Added reproducible live schema type generation through `npm run types:supabase`.
- Added `docs/architecture/DATABASE_CONTRACT_AND_TYPING.md`.
- Improved Supabase read mappings so merchant/category application identities are restored from `external_key` rather than leaking relational UUIDs.

## Verification model

M0.9 uses three layers:

1. **Committed migration contract** — available now and enforced in CI.
2. **Live Supabase schema smoke test** — available as a script; requires the real project and service-role environment.
3. **Generated database TypeScript definitions** — reproducible; requires the real Supabase project ID.

## External completion gate

The following cannot be truthfully marked complete until the real Supabase project exists:

- remote migration application;
- live connection smoke test;
- generated `database.types.ts` from the actual schema;
- wiring the generated `Database` type into the Supabase client;
- preview-environment synthetic import against real Postgres;
- live security/RLS review.

## Acceptance criteria already met

- Database assumptions are represented in committed migrations.
- CI verifies the critical schema contract without network credentials.
- Live verification is read-only and reproducible.
- Live type generation is scripted rather than manual.
- Relational UUIDs remain implementation details behind stable Winkelnu `external_key` identities.
- M0.8 type errors discovered by CI have been corrected in source.

## Next technical phase

While the external Supabase gate remains pending, work can continue independently on **M0.10 — Automated Catalog Test Harness**, using the in-memory adapter to prove import, matching, rejects, stale offers and storefront contracts deterministically.
