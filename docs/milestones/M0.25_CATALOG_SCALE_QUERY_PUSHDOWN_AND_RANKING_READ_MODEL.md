# M0.25 — Catalog Scale Query Pushdown & Ranking Read Model

Status: repository-side implemented; CI verification pending.

## Delivered
- `CatalogRankingReadModel` application port.
- `ScalableCatalogService` for Supabase storefront reads.
- `SupabaseCatalogRankingReadModel` adapter.
- Migration `0008_catalog_ranking_read_model.sql`.
- Service-role-only `catalog_ranked_products` RPC.
- Supporting lower-case search and active-offer ranking indexes.
- Database-contract verification for migration 0008/RPC.
- Tests proving listing/search use the read model instead of legacy N+1/application filtering.
- Updated Supabase activation runbook.

## Scale effect
Supabase product listings no longer require one product-detail query per listed product. Search no longer needs to fetch a bootstrap set capped at 240 products before filtering. Ranking, freshness exclusion, core filters and pagination are pushed into Postgres.

## Preserved invariants
- landed price remains product price + known shipping;
- expired offers (>72h since lastSeenAt) do not rank;
- stale offers remain usable through 72h;
- in-stock/min/max filters apply to the true best offer, not a promoted alternate;
- public routes keep using the same CatalogService surface;
- memory mode remains deterministic and unchanged.
