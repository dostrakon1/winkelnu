# M0.14 — Affiliate Redirect & Click Attribution Architecture

Status: COMPLETE (repository-side; live Supabase verification pending)
Date: 2026-09-03

## Goal

Introduce a stable, safe outbound affiliate boundary so storefront pages no longer depend directly on merchant affiliate URLs and successful outbound clicks can be attributed to durable Winkelnu offer identities.

## Implemented

- `AffiliateRedirectService` application boundary.
- Separate `AffiliateAttributionRepository` port.
- In-memory attribution adapter for deterministic development/tests.
- Supabase attribution adapter for production persistence.
- Stable outbound route: `/uit/[offerId]`.
- Stored-offer destination resolution; no public destination query parameter.
- Fail-closed behavior for missing, inactive and invalid offers.
- Internal unavailable-offer fallback page.
- Privacy-minimal click event model.
- Migration `0004_affiliate_click_attribution.sql`.
- Database-contract verification extended through migration 0004.
- Supabase smoke-test table list extended with `affiliate_click_events`.
- Product detail CTAs now route through Winkelnu instead of linking directly to affiliate destinations.
- Automated redirect safety and click-attribution tests.
- Architecture documentation in `docs/architecture/AFFILIATE_REDIRECT_AND_CLICK_ATTRIBUTION.md`.

## Baseline privacy decision

The click event does not store raw IP addresses or user-agent fingerprints. Only offer/product/merchant attribution, optional internal source path and timestamp are recorded.

## Safety rules

- destination must come from the stored offer;
- destination must be HTTPS;
- embedded URL credentials are rejected;
- inactive offers do not redirect;
- invalid/missing offers fall back internally;
- source attribution accepts only a relative internal path;
- a click is recorded before a successful redirect is returned.

## External completion gate

A live Supabase project is still required to prove:

- migration 0004 applies remotely;
- `affiliate_click_events` is readable by the server service role;
- one successful `/uit/<offer-id>` request writes exactly one live event;
- the stored destination resolves correctly in preview/production.
