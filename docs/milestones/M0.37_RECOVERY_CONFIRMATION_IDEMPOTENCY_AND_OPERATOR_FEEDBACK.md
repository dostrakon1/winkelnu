# M0.37 — Recovery Confirmation, Idempotency & Operator Feedback

Status: repository-side implemented; CI verification pending.

## Delivered
- browser confirmation before feed pause;
- pending/disabled recovery buttons while actions execute;
- explicit success, duplicate and error feedback;
- server-side request-key idempotency before recovery mutation;
- `operator_action_requests` RLS-protected service-role ledger;
- duplicate submits skip both the second mutation and duplicate audit events;
- tests covering duplicate retry suppression;
- database contract extended through migration `0013`.

## Safety invariants
- UI state is not the security boundary;
- every action rechecks the human session and role server-side;
- every first execution still passes the immutable M0.35 audit boundary;
- a request must be claimed before mutation;
- unexpected idempotency persistence failure fails closed;
- no credentials or tokens are stored in the idempotency ledger.

## External gate
Live verification still requires an actual Supabase project with migrations `0001` through `0013`, a configured operator account and a real feed source.

## Next
