# M0.10 — Automated Catalog Test Harness

Status: Implemented; CI verification in progress
Date: 2026-09-03

## Objective

Protect the catalog foundation with deterministic automated tests before real affiliate feeds and production persistence are introduced.

## Test stack

- Vitest 4.1.x
- Node environment
- TypeScript source directly under test
- `@` alias mapped to `src/`
- Tests run in GitHub Actions before the production build

## Covered rules

### Matching

- Exact GTIN produces a certain canonical identity.
- Brand + MPN produces a high-confidence canonical identity when GTIN is unavailable.
- Missing strong identifiers preserve source identity and require review.

### Import safety

- Valid records enter the catalog.
- Duplicate merchant product IDs in one run are rejected.
- Invalid records stay out of the catalog and retain diagnostic reasons.
- Weak source-identity matches are queued for review.
- Offers missing from a later successful complete feed are deactivated.

## CI order

1. install dependencies;
2. verify database migration contract;
3. lint;
4. TypeScript typecheck;
5. automated tests;
6. production build.

Any failure blocks a green Quality run.

## Commands

```bash
npm run test
npm run test:watch
npm run check
```

## Acceptance criteria

- Core matching rules have deterministic tests.
- High-risk import safety behavior has deterministic tests.
- Tests do not require live Supabase or external affiliate services.
- CI runs the tests before building.
- The test harness can be extended per merchant adapter without coupling tests to production infrastructure.
