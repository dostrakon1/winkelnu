# M0.15 — Affiliate Network & Merchant Integration Registry

Status: Completed repository-side.
Date: 2026-09-03.

## Goal

Create an explicit registry for affiliate networks, merchant programs and feed-source relationships so future partner integrations can be added without leaking vendor-specific assumptions into catalog, offer or storefront layers.

## Delivered

- affiliate network domain model;
- merchant affiliate integration domain model;
- feed-source integration registration model;
- application registry service and repository port;
- direct/network/marketplace validation rules;
- environment-secret reference validation;
- in-memory registry repository;
- Supabase registry repository;
- migration `0005_affiliate_integration_registry.sql`;
- feed source → affiliate integration relation;
- offline database contract verification;
- live Supabase smoke-test coverage;
- automated registry invariant tests;
- architecture documentation.

## Security baseline

Actual partner credentials are never stored in registry rows. The registry stores only references such as `env:AFFILIATE_PARTNER_API_TOKEN`.

`tracking_config` is restricted by architecture to non-secret metadata.

## Acceptance criteria

- [x] merchant and affiliate network are separate entities
- [x] direct partner programs do not require a fake network
- [x] network/marketplace integrations require a matching active network
- [x] feed sources can be attributed to a concrete merchant integration
- [x] feed source and integration merchant identities must match
- [x] real credential values are rejected by the application registry contract
- [x] Postgres UUIDs remain internal while domain IDs remain stable external keys
- [x] database contract and smoke-test tooling include the registry schema
- [x] registry rules have automated tests

## External gate

The migration has not been applied to a live Supabase project yet. Live project verification remains part of the existing Supabase activation gate.
