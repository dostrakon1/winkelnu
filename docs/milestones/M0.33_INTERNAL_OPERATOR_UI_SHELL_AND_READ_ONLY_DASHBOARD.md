# M0.33 — Internal Operator UI Shell & Read-Only Dashboard

Status: repository-side implemented; CI verification pending.

## Doel

De beveiligde operations read surface vertalen naar een bruikbare interne operatorpagina zonder beheerwrites of publieke adminomgeving.

## Geïmplementeerd

- server-rendered `/intern/operations` App Router page;
- server-side Bearer authorization;
- unauthorized requests worden als 404 behandeld;
- `noindex`, `nofollow`, `nocache` metadata;
- directe server-side koppeling aan `PartnerOperationsReadService` en `buildOperationsDashboard()`;
- compacte metrics voor integrations, actieve integrations, feeds, incidents en critical/high;
- incidentkaarten in bestaande severityvolgorde;
- concrete operatoractie per incident;
- read-only UI zonder mutations;
- architectuurdocumentatie.

## Securitygrenzen

- geen service-role key in browsercode;
- geen ops secret in client props;
- geen credentialwaarden of secret refs in de UI;
- geen publieke `/admin` route;
- geen claim dat Bearer-header auth de uiteindelijke menselijke loginervaring is.

## Live gate

De pagina kan pas echte inhoud tonen nadat een live Supabase-project is geconfigureerd en partner/feeddata aanwezig is. De huidige route-auth is geschikt voor interne tooling/reverse proxy; een human session/loginlaag is een aparte toekomstige stap.

## Volgende stap

M0.34 — Human Operator Authentication & Session Boundary: een echte server-side menselijke login/sessionlaag ontwerpen zodat de interne pagina veilig via normale browsernavigatie gebruikt kan worden zonder Bearer-secret in de browser te beheren.
