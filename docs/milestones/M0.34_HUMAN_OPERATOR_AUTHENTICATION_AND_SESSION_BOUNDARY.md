# M0.34 — Human Operator Authentication & Session Boundary

Status: repository-side implemented; CI verification pending.

## Doel

Een normale beveiligde browserlogin toevoegen voor Winkelnu Operations, zonder Bearer-secret in de browser en zonder publieke signup.

## Geïmplementeerd

- `@supabase/ssr` toegevoegd;
- cookie-based server auth client;
- Next.js `proxy.ts` voor `/intern/:path*` session refresh;
- `/intern/login` e-mail/wachtwoord login via Server Action;
- server-confirmed usercontrole via `auth.getUser()`;
- fail-closed `WINKELNU_OPERATOR_EMAILS` allowlist;
- `/intern/operations` beschermd door human operator session;
- logoutactie;
- machine `/api/ops/*` Bearer-auth blijft apart;
- tests voor allowlist-normalisatie en fail-closed gedrag;
- architectuurdocumentatie.

## Niet gedaan

- geen publieke signup;
- geen user-management UI;
- geen rollenbeheer in database;
- geen live Supabase operatoraccount aangemaakt;
- geen claim dat Auth live geconfigureerd is.

## Volgende stap

M0.35 — Operator Authorization Roles & Audit Boundary: owner/operator/read-only rollen en minimale audit events ontwerpen voordat interne write-acties ooit worden toegestaan.
