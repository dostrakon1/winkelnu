# M0.16 — Partner Adapter Registration & Feed Source Resolution

Status: repository implementation complete; real partner adapter onboarding pending.

## Goal

Resolve a registered feed source into its active affiliate context and then select the correct infrastructure adapter without introducing provider-specific dependencies into domain or application code.

## Implemented

- `PartnerFeedSourceResolver` application service;
- fail-closed validation for inactive/missing source, integration and network context;
- merchant ownership consistency checks;
- network/integration kind consistency checks;
- `PartnerFeedAdapterRegistry` in infrastructure;
- deterministic adapter keys based on network/direct/generic source context;
- server-only `env:` credential resolution inside infrastructure;
- `resolvePartnerFeedAdapter()` composition helper;
- automated tests for commercial resolution, adapter selection, credential isolation and missing-adapter failure;
- architecture documentation in `docs/architecture/PARTNER_FEED_ADAPTER_RESOLUTION.md`.

## Boundary proven

The ingestion layer can keep consuming the existing generic `FeedAdapter` interface while partner-specific selection happens only in infrastructure.

No API token or resolved credential is returned by `PartnerFeedSourceResolver` or stored in domain/application models.

## External/next gate

No real affiliate provider adapter is connected yet. The next milestone should introduce a provider adapter contract fixture and one realistic end-to-end partner adapter proof using non-production fixture data before live credentials are introduced.
