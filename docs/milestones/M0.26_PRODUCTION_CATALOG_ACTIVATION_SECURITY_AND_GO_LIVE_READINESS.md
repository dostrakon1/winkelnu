# M0.26 — Production Catalog Activation, Security & Go-Live Readiness

Status: repository-side implemented; live Supabase activation pending external project access.

## Delivered
- Migration `0009_production_security_and_readiness.sql`.
- RLS enabled on all 13 sensitive public-schema tables.
- No anon/authenticated table policies added; catalog access remains server-only by default.
- `winkelnu_production_readiness()` service-role-only RPC.
- `supabase/seed.sql` with deterministic category bootstrap data only.
- `npm run verify:production-readiness` live readiness command.
- Database contract now fails when required RLS or readiness RPC is missing.
- Preview-to-production go-live checklist and stop conditions.

## Security baseline
The service role bypasses RLS and is used only in trusted server-side code. Browser clients do not receive the service-role key and no public table policies are introduced in this milestone. RPC execution for operational/read-model functions remains explicitly revoked from `PUBLIC` and granted only to `service_role`.

## External gates
This milestone does not claim that migrations are applied remotely, that RLS has been observed on a live project, or that live RPCs have passed. Those require the real Supabase project URL/service-role credentials and must be verified with the committed readiness commands.
