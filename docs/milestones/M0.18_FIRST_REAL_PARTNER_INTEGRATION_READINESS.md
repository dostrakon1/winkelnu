# M0.18 — First Real Partner Integration Readiness

Status: repository-side complete; external Daisycon account/approval/sandbox gates pending.

## Goal

Prepare Winkelnu for its first real affiliate partner integration without enabling production credentials or live imports prematurely.

## Chosen first provider

Daisycon.

Reasons:
- strong fit for Dutch publisher/comparison use-cases;
- explicit publisher product-feed tooling;
- JSON/XML/CSV feed delivery;
- OAuth-based API access;
- sandbox environment;
- documented throttling and HTTP 429 behavior;
- product-feed pagination through `X-Next-Url` for single-program feeds.

## Implemented

- `DaisyconProductFeedAdapter` transport layer.
- JSON product-feed support.
- injected mapper/extractor boundary so campaign/feed-standard fields do not become domain contracts.
- same-origin validation for provider pagination URLs.
- HTTPS-only feed URLs.
- redirect refusal at fetch level.
- bounded retry handling for 429 and 5xx.
- bounded `Retry-After` handling.
- fail-closed handling for 4xx and unsupported JSON shapes.
- Daisycon adapter registration helper for `daisycon:json`.
- baseline common-field mapper into `FeedCandidate`.
- environment contract for product feed URL and future OAuth/API metadata access.
- automated tests for mapping/pagination, 429 retry, SSRF-origin protection and failure behavior.
- architecture/readiness document with sandbox/read-only activation gate.

## Security decisions

- Generated feed URL is treated as a server secret.
- OAuth client secret is server-only.
- no Daisycon values receive a `NEXT_PUBLIC_` prefix.
- `X-Next-Url` may not change origin.
- public requests can never provide a provider feed URL.
- provider records still pass the normal Winkelnu validator after mapping.

## External completion gates

Not yet available and therefore not claimed complete:
- Daisycon publisher account/media approval;
- Daisycon developer app/OAuth credentials;
- merchant/program approval;
- generated real JSON feed URL;
- sandbox connectivity;
- sanitized real feed sample;
- live mapper verification;
- preview import against real Daisycon data.

## Exit condition

Repository architecture is ready for those external values without requiring a redesign of catalog import, affiliate registry or storefront contracts.
