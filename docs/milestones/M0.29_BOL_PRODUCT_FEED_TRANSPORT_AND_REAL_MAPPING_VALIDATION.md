# M0.29 — bol Product Feed Transport & Real Mapping Validation

Status: repository-side implemented; live bol feed access gate pending.

## Goal
Prepare the bol Affiliate product-feed ingestion boundary so real feed access can be connected without guessing transport details or schema fields.

## Implemented
- streaming-oriented `BolProductFeedTransport` port;
- documented bol `.csv.gz` feed filename recognition;
- official pipe-delimited first-row header parsing;
- explicit header-driven `BolProductFeedMappingProfile`;
- schema inspection for duplicate/missing bindings;
- row parser with column-count fail-closed behavior;
- conversion to Winkelnu `FeedCandidate`;
- automatic bol Productfeed tracking URL construction using the configured Site_ID;
- sample validator using the existing catalog candidate validator and 95% acceptance baseline;
- tests for filenames, schema, mapping, tracking and fail-closed sample validation;
- architecture documentation separating verified provider facts from fixture assumptions.

## Deliberately not implemented
No production FTP client/host configuration is invented. The current account-specific bol connection details, IPv4 whitelist and real feed header have not been supplied.

Synthetic test header names are not an official bol schema claim.

## External completion gates
M0.29 becomes live-validated only when:
1. bol Affiliate product-feed access is enabled for Winkelnu;
2. current FTP connection instructions/credentials are available server-side;
3. the correct outbound IPv4 is whitelisted;
4. a current feed file is downloaded;
5. its exact header and a sanitized sample are validated;
6. the resulting profile passes the M0.27/M0.28 production acceptance gates.
