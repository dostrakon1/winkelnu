# M0.4 — Persistence & Catalog Schema Design

Status: FOUNDATION COMPLETE
Date: 2026-09-03

## Goal
Define the first durable data model for a multi-merchant affiliate/comparison catalog before any partner-specific feed is connected.

## Implemented schema
Migration: `supabase/migrations/0001_catalog_foundation.sql`

Core tables:
- `merchants`
- `categories`
- `products`
- `feed_sources`
- `import_runs`
- `offers`
- `product_identifiers`

## Key decisions
- Winkelnu products are canonical entities independent of merchants.
- Offers are merchant-specific and carry price, freshness and affiliate destinations.
- Merchant product IDs are unique inside a merchant, not globally canonical.
- Feed source configuration and import audit history are separate from catalog data.
- Matching identifiers are first-class data so product deduplication can evolve without corrupting canonical product identity.
- Financial values use Postgres `numeric` and precision-safe string amounts in TypeScript domain contracts.
- Soft publication states are preferred over destructive deletion for canonical products.

## Not activated yet
This migration is committed but not applied to a live Supabase project. That is deliberate: applying it requires an external Supabase project and credentials.

Row Level Security policies are also deferred until the public-read/admin-write model and authentication boundary are finalized. No table should be exposed publicly before those policies exist.
